# OnDeviceRAG 0.2.0 — Conversation history (and document rename)

Status: design approved 2026-10-25, not yet implemented. Extends `design.md` (§5 API, §7 retrieval).

## 1. Goal

Chat apps built on OnDeviceRAG need conversation history in two places:

1. **Search:** a follow-up such as *"and what about lists?"* doesn't name its topic, so the
   previous questions must join the search query.
2. **The prompt:** the model should see the latest turns ("explain that again more simply").
   The package can't write the prompt (every app words it differently), but it can do the
   hard, model-independent part: choose which recent turns fit a token budget.

Both are **switches, off by default**, so apps that don't want history (or runs that must stay
identical, e.g. research experiments) are unaffected.

## 2. Public API

```swift
public struct ChatTurn: Sendable, Hashable, Codable {
    public enum Role: String, Sendable, Codable { case user, assistant }
    public var role: Role
    public var text: String
    public init(role: Role, text: String)
    public static func user(_ text: String) -> ChatTurn
    public static func assistant(_ text: String) -> ChatTurn

    /// "User: …" / "Assistant: …" lines, oldest first, separated by blank lines.
    public static func format(_ turns: [ChatTurn], userLabel: String = "User",
                              assistantLabel: String = "Assistant") -> String
}

public struct HistorySettings: Sendable, Hashable {
    /// Switch 1: add recent user turns to the search query.
    public var useForSearch = false
    /// Switch 2: return the recent turns that fit `tokenBudget` in `RAGContext.history`.
    public var includeInContext = false
    /// User turns added to the search query (newest first, after the question).
    public var searchTurns = 2
    /// Most turns returned for the prompt.
    public var maximumTurns = 6
    /// Token budget for the returned turns — separate from the sections' budget.
    public var tokenBudget = 600
    public init() {}
}
```

- `RAGConfiguration` gains `public var history = HistorySettings()`.
- `RetrievalSettings.historyMessages` is removed (replaced by `history.searchTurns`).
- `RAGEngine.search(_:history:limit:)` and `context(for:history:tokenBudget:)` take
  `history: [ChatTurn] = []` (oldest first) instead of `[String]`.
- `RAGContext` gains `public let history: [ChatTurn]` (kept turns, oldest first; empty unless
  `includeInContext`) and `public let historyTokenCount: Int` (0 when empty). Its existing fields
  are unchanged; `tokenCount` still counts the sections only.

## 3. Behavior

- **Both switches off (default):** `history` is ignored. Results are identical to calling without
  history.
- **`useForSearch`:** the query is the question followed by the last `searchTurns` **user** turns,
  newest first (assistant turns are never searched — long, and in the model's words). Same
  ordering rule as before, so the embedder's 512-token truncation only ever cuts history.
- **`includeInContext`:** walk the turns from newest to oldest, at most `maximumTurns`; count each
  turn with the engine's token counter (on its `format`ted line with the default labels); add it
  while the running total fits `tokenBudget`. **The first turn that doesn't fit ends the window**, so
  the result is always an unbroken run of the latest turns (no gaps). Turns are never cut. A single
  turn larger than the whole budget therefore yields no history — documented, and the reason the
  budget is configurable.
- Token counts use the same cached counter as packing (`CachingTokenCounter`), so repeated turns
  are counted once.
- **No storage:** the package doesn't save conversations; the app owns its chat log and passes it in.

## 4. Document rename

`RAGEngine.renameDocument(id: DocumentID, to title: String) async throws -> DocumentInfo`:
re-chunks the document from its stored source with the new title (the title heads text documents'
first section and every packed block), re-embeds it, saves it (persistent engine), and keeps its
added-at date. Throws `RAGError.prebuiltDocument` for prebuilt documents and a new
`RAGError.unknownDocument(id)` for an unknown ID.

## 6. Compatibility (changelog)

- **Breaking:** `history` is `[ChatTurn]` instead of `[String]`; `RetrievalSettings.historyMessages`
  removed. 0.x minor bump → **0.2.0**. Apps on "Up to Next Minor from 0.1.0" must change their rule
  to "from 0.2.0".
- **Behavior:** passing history no longer changes search unless `history.useForSearch` is on.
- Stored documents and `.ragindex` files are unaffected (no format change).

## 7. Testing (Mac, fake embedder, tally token counter)

- Switches off → same chunks / same context as no history.
- `useForSearch` → query contains the question and the last 2 user turns, never assistant turns.
- `includeInContext` → newest turns kept, oldest dropped; `maximumTurns` respected; budget respected;
  window stops at the first turn that doesn't fit (an older small turn after a big one is *not*
  included); empty history → empty; `historyTokenCount` equals the sum of kept turns' counts.
- `ChatTurn.format` output.
- Rename → packed text and `documents` show the new title; persists across reopen; prebuilt and
  unknown IDs throw.
- All existing tests still pass; mutation checks on the new logic.

## 8. Out of scope

Query rewriting with a language model, summarizing old turns, saving conversations, per-call
overrides of the switches (pass no history instead).
